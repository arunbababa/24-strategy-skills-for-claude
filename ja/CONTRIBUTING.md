# 貢献

PR と Issue を歓迎する。

## 新しいスキルの追加

1. 最も近い既存スキル（例：`skills/situation-assessment/`）の構造をコピーする。
2. 各 `SKILL.md` に、`name` と `description` を持つ YAML frontmatter を付ける。`name` はフォルダー名に完全一致させる。`description` は何をするスキルかと、いつ使うかの両方を述べる。Claude が適用するかの判断に使うため、適用のきっかけとなる表現を具体的に書く。
3. 他の全スキルと同じ本文構造に従う。**使用する場面 → 実行すること → 方法 → 入力 → 出力形式 → 例 → よくある落とし穴**。
4. 定量的なスキルなら、テスト済み Python スクリプトを持つ `scripts/` フォルダーを加える。十分な理由がない限り標準ライブラリ以外の依存を加えず、どこでも実行できるようにする。
5. README のアルファベット順の表、該当カテゴリーの節へスキルを追加する。総数が変わるなら上部のバッジの件数も更新する。
6. 提出前に、現実的な具体例で計算ツールをテストする。説明用の数字を創作せず、実際の出力をスキルの**例**へ貼る。

## 既存スキルの改善

- 同じ構造を維持し、節を削除しない。
- 計算ツールの修正では、PR の説明へテスト事例の修正前・後の出力を入れる。
- スキル間参照に関わる変更（例：`value-realization` から `business-case-builder` への参照）なら、編集後も参照が正確か確認する。

## バグ報告

対象スキル、期待した結果、実際の結果、計算ツールのバグなら再現する入力を含めて Issue を作る。

## 対象範囲

このパックは、一般的な「アイデアを出す」プロンプトではなく、実際のコンサルティング方法論（マッキンゼーが文書化した実務構造）を明確な方針として重視する。新スキルでは、題目の説明だけでなく、具体的で名前のある方法を教える。
